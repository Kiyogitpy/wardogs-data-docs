# Wardogs — Item and Player Actions
*Extracted from every `BHActionDefinition` and `WDActionDefinition` asset in the exports (155 assets: 134 `BHActionDefinition` and 21 `WDActionDefinition`), plus the item-side bindings in `ID_*` item assets. Cooked data only (UE 5.7, `++Wardogs+Live-CL-516586`). The tables are generated by [`_tools/action_tables.py`](../_tools/action_tables.py); do not edit them by hand.*

> **Labels.** **Data** = read from an exported asset. **Derived** = a reading of the names and the data together, not confirmed in native code. **Native** = traced in the game binary. **Not traced** = neither the data nor the code read says. This page has no **Native** claims; every behavior note is **Data** or **Derived** unless it says otherwise.

An *action* is something the character does: fire, reload, sprint, heal, throw, emote. An action definition asset describes one action: its tag, which blueprint runs it, and which other actions it blocks, interrupts or buffers. Items choose which action tag each input starts. How the pieces connect:

1. An item (`ID_Bandage`) lists *input behaviors*: input tag `Input.NamedActions.Appliable.PrimaryUse` starts action tag `Action.Appliable.Bandage.PrimaryUse` (**Data**, section 7).
2. The action tag finds its `DA_Action_*` definition (sections 4 and 5). The definition names the class that runs the action and the rule list for conflicts with other actions.
3. Item-specific numbers (heal amount, how the use time is decided, units consumed) are on the item, not on the action (section 6).
4. Some actions also apply GameplayEffects while they run (section 8).

The earlier overview is [GameMechanics §4](Wardogs_GameMechanics_v2.md#4-action-definitions-actions-116-bhwd-action-definitions). This page is a separate page, not a section of GameMechanics, because the tables are generated, are about 150 rows, and join three asset families (actions, items, effects) that GameMechanics §4 only lists by folder.

## 2. What the fields mean

| Field | Meaning | Label |
|---|---|---|
| `ActionTag` | The action's identity (`Action.Weapon.Reload`). Items, input behaviors and the response rules all refer to actions by this tag. | **Data** |
| `ActionContext` | Context flags (`Holdable`, `Weapon`, `Interaction`, `TwoHanded`, `OneHanded`, `Movement`, `UI`, `Emote`, `FollowProjectile`). They describe the action and are also the *categories* that `BlockCategories` and `InterruptCategories` rules name. | **Data** for values; category use is **Derived** |
| `ActionClass` | The blueprint (or the native `WDGameplayAction`) that runs the action. Shown by class name only. The medical, throw, place and build `B_Action_*` blueprints were exported in round 17 (durations are the montage lengths in section 6.1); cancel logic inside them is not traced. | **Data** (class name); logic **not traced** |
| `ActivationContextType` | A struct type carrying what the action needs when it starts (`WDAppliableItemActionContext` for item use, `WDEmoteActivationContext` for emotes, `BHTraversingActivationContextData` for vault and mantle). | **Data** |
| `ActionResponseData` | The conflict rules, a map from a response type to lists (section 3). | **Data** |
| `ActionEffects` (`WDActionDefinition` only) | GameplayEffects tied to the action by a key name (section 8). | **Data** |
| `bInstantAction` | The action has no duration. Set on 6 assets (door use, jump, stop-sprint, stop-tac-sprint, toggle hands, throw swap). | **Data**; exact use **not traced** |
| `bRebufferAction` | Set on `DA_Action_Chamber` only. | **Data**; meaning **not traced** (the name suggests it can be buffered again) |
| `bConsumeAxisInputOnCompletion` | Set on `DA_Action_Vehicle_Weapon_ActiveReload` only. The name suggests the axis input is consumed when the action completes. | **Data** / **Derived** |
| `_aaabhcpaaifhekodaalnj`, `_aaacbmicphngedjgincpn` | Two obfuscated booleans on the base class (SDK offsets `0xB9` and `0xBB`). The first is true on `DA_Action_UI_ChangeQuickSlot`; the second is never true. | **Data**; meaning **not traced** |

**Fields that do not exist on the action.** The definition has no duration, cooldown, montage, item-consumption, granted-tag or input-binding field. Where those concepts exist in the data they are on other assets:

| Concept | Where it is | Label |
|---|---|---|
| Use time of a consumable | `WDItemExtensionData_Appliable.AppliableActionData[tag].InteractionTimeMethod` (`AnimationLength`, `AnimationNotifier`, `UntilItemEmptyOrTargetFull`), section 6 | **Data** |
| Animation | An animation *tag* (`Animation.Asset.Appliable.PrimaryUse`), never a montage path | **Data** |

## 3. Response rules (`ActionResponseData`)

Each entry has a response type and up to six lists. The type decides how the lists are read. The plain meanings below are **Derived** from the names and the entries; how the action system evaluates them is **not traced**.

| Response type | Plain meaning |
|---|---|
| `Interrupt` | Starting this action cancels the listed actions if they are running (bandage use cancels sprint). |
| `Block` | While this action runs, the listed actions cannot start (reload blocks inspect and a second reload). |
| `BlockingStates` | This action cannot start while the character has one of the listed states (reload is refused when `Vitality.Critical` or `Vitality.Dead`). |
| `InterruptCategories` | Like `Interrupt`, but by context flag (an emote cancels other emotes). |
| `BlockCategories` | Like `Block`, but by context flag. |
| `Buffer` | If the listed action is requested while this one runs, remember the request for `BufferTime` seconds. `FullBuffer` and `PartialBuffer` are the two buffer types; the difference is not traced. |
| `InterruptBuffered`, `InterruptAndBuffer`, `InterruptOnComplete` | Combinations of interrupt and buffer, or an interrupt tied to completion. |
| `RequiredStates` | The character must have the listed state to start the action. |
| `None` | Present but empty. |

Tags in the tables drop the `Action.` prefix (`Player.Sprint` is `Action.Player.Sprint`). Tags under `BlockingStates` and `RequiredStates` drop `State.Player.`; category tags drop `Action.Context.`. `Block` and `Interrupt` lists can also name states such as `State.Player.Movement.Custom.Ladder`; those appear in full.

## 4. Definitions and rules by item family

Each family has two tables. The first gives the definition (what the asset is and which items bind it). The second gives the conflict rules. Rows with identical contents are merged and list their assets together. "Bound by items" lists the `ID_*` item assets whose input behaviors start the action (first five); `—` means no item binds it (movement, UI and generic weapon actions are started by the character, not by an item) and `release only` means an item only completes it.

## 5. Worked examples

- **Bandage** (`DA_Action_Bandage_PrimaryUse`): blocks `Bandage.SecondaryUse` while running and interrupts `Player.Sprint` and `Player.TacSprint`. It has no `BlockingStates`, so the definition does not stop the use when downed; the owner-state check is on the item (`Vitality.Alive`, section 6). **Data**.
- **Reload** (`DA_Action_Reload`): refused when `Vitality.Critical` or `Vitality.Dead`; interrupts fire, inspect, focus and both sprints; blocks inspect, sight cycling, a second reload, the vendors, bipod fold and door use; buffers `Weapon.Fire` for 0.6 s and `Player.Focus` for 2 s; interrupts the `Emote` category. **Data** for each list; the ordering effects are **Derived**.
- **Jump** (`DA_Action_Jump`, a `WDActionDefinition`): an instant action that applies `GE_Player_Jump` and buffers reload and stance requests for a short time. The effect is in section 8.

How to read it:

- **Heal / attribute.** The attribute the item changes and the amount. `(delta)` means `bApplyAsDelta` is true (added to the current value). For the defibrillator the flag is not stored, so the mode is not confirmed. Heal amounts are also on [Items §5](Wardogs_Items_v2.md). Heal rates, applied effects, use costs and the medic skills that change them are on [Medical and Healing](../game-features/Wardogs_Medical_v1.md). **Data**.
- **Time method.** `AnimationLength`: the use lasts as long as the animation. `AnimationNotifier`: it completes at an animation notify (`Heal`). `UntilItemEmptyOrTargetFull`: the use continues until the item runs out or the target is full (fuel can, repair tool, resuscitator). The method name is **Data**; the seconds are the montage lengths in section 6.1 (**Data (Blueprint CDO)**, [round 17 evidence](../docs/evidence/round17-blueprint-defaults.md)).
- **Consumed per use.** `AmountConsumedOnUse` (1 for almost all). **Data**.
- **World interaction.** A context class names the interaction that targets another player or a vehicle (`WDHealPlayerInteractionContext`, `WDVehicleRepairInteractionContext`). **Data**.
- **Container.** `bContainerAppliable` marks items that hold a quantity (fuel, repair charge). **Data**.

Plain reading of the main ones (**Derived** from the modifiers):

- `GE_UseAppliable` halves movement speed (compound multiplier 0.5) while it is active. Bandage, IFAK, resuscitator and StimPen list it as an applied effect on the item, so using a consumable slows the user. The binoculars and range finder actions reference the same effect.

- `GE_Defib` only grants `State.Player.Action.Appliable.Reviving.Friendly`.
- The stance, jump, vault, mantle and stop-sprint effects scale weapon-sway multipliers by the character's weight through a curve; the stance effects also grant the stance state tag.
- `GE_DoorBreach` lasts 0.8 s and ramps movement speed along `CT_DoorMovement`.
