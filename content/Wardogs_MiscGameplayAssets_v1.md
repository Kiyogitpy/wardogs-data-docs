# Wardogs: Misc Gameplay Assets (modifier states, controller presets, doors)

*Source: the export files under `data/Wardogs/Content/MoverTesting/CharacterModifierStates`, `data/Wardogs/Content/GameMechanics/Settings/Controls` and `data/Wardogs/Content/GameMechanics/WorldInteractable/Objects`. Every table below is generated by [`_tools/misc_gameplay_tables.py`](https://github.com/Kiyogitpy/wardogs-data-docs/blob/main/_tools/misc_gameplay_tables.py); do not edit it by hand.*

This page closes the gap left by [Character Movement Settings](Wardogs_MoverTesting_v2.md), [Settings and Inputs](Wardogs_SettingsAndInputs_v1.md) and [Player Movement](Wardogs_PlayerMovement_v1.md): it lists, with values, the assets in those three folders whose name appears on no other published page (the generator re-checks that on every run, so an asset documented elsewhere later drops off here). The user-setting rows themselves (dead-zone values, sensitivity, look acceleration) are on Settings and Inputs; tags are on [Gameplay Tags](Wardogs_GameplayTags_v1.md).

## How to read a row

- Values are as exported. Each row flattens the asset's properties to `path=value`; tags show as the tag name, references as the referenced asset name, curve key lists as `time->value` points. Null and empty values are dropped, and a long cell ends with `(+N more values)`.
- Where the export omits a value (for example a state `Priority`), the table says "omitted" and does not resolve the native class default.
- What an asset type is for is **inference** from the class and property names. The export stores no documentation. In particular the two obfuscated `_aaab...` properties of the controller presets are read as "binding rows" and "mapping context paths" from their contents only.
- Left out on purpose: audio, VFX and UI-widget assets. None of these three folders hold any, so nothing was skipped here.

## 2. Character modifier states

Folder `MoverTesting/CharacterModifierStates`. Each file is a `WDCharacterModifierStateDefinition` (a state tag, a priority, a list of modifier objects and a list of condition objects) plus the modifier and condition objects it references, stored as extra exports in the same file. Inference: a state is active while its conditions pass, and the modifiers apply camera, animation or movement adjustments; the highest priority presumably wins on conflict. `WDCharacterModifierCondition_StateTags` conditions show the tag query's dictionary and description text; `QueryTokenStream` (the compiled query) is shown as a number list. The curves named here (`CRV_*`) are on [Character Movement Settings](Wardogs_MoverTesting_v2.md) or its curve data.

## 3. Gamepad dead-zone presets

Folder `Settings/Controls`. Each preset asset pairs an enum list (the preset names shown in the options menu) with `SettingPresets` slots, one per enum entry in order; a slot assigns values to the user-setting tags. Slot index to name follows the order of the named values (inference); the last named value, `Custom`, has no slot, so it leaves the three values to the player. Values are percentages (inference from the 0 to 100 trigger range).

## 4. Axis config

`DA_Player_InputAxisConfig` (`BHAxisConfigDataAsset`) says which user setting feeds each look-axis modifier, first as a default and then per state: a state block applies when every tag group matches (a group matches when any tag in it is present; the AND/OR reading is inference from the nested list). `Axis` is X, Y or XY; `Gamepad` marks the gamepad variants. Setting property names are those of the user-setting rows on [Settings and Inputs](Wardogs_SettingsAndInputs_v1.md).
