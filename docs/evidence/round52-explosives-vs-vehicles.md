# Round 52: hits to destroy a vehicle with each anti-vehicle explosive

Static analysis only. Nothing was run in game. Status labels: FOUND (read in cooked data or Blueprint), NATIVE (read in the executable), SERVER (decided server side, not visible), ABSENT (searched for, not there).

Generated by `python -I _tools/round52_explosive_hits.py` into `assets/data/explosive-hits-vs-vehicles.json` (`--wiki` prints the wiki tables). The tool reuses `_tools/damage_tables.py` (rule evaluator, section routing, `hits_to_destroy`) and `_tools/explosive_tables.py` (explosive rows, falloff). It extends the four-vehicle table of the [Explosives Reference](../../game-features/Wardogs_Explosives_v1.md) (section 5) to every vehicle variant and emplacement and to all anti-vehicle sources. The four vehicles of that table were re-derived and match (Little Bird 122 mm 5, Humvee 93 mm 6, T-72 125 mm 4, and so on).

## Why the wiki said "not in the hits table"

R52-1. The note in `vehicle-comparison.md` ("The vehicle articles give no hit counts for them") was a scope statement, not a finding that the counts cannot be derived. The vehicle articles were built from the bullet and cannon simulation (`damage_tables.py --survive`), which has no explosive columns. The explosive counts already existed for four vehicles in the Explosives Reference and the vehicle viewer carries per-caliber `blast_factor` and per-actor `explosion_factor` for all 23 vehicles. Nothing is missing from the data for a direct or inner-radius hit. Status: FOUND.

## The formula

Per blast on one vehicle, with Base B, inner radius E, outer radius R, falloff F, minimum M (all from the projectile asset or explosive actor):

1. Distance d from the blast origin to the accepted hit. Amount `A(d)`:
   - d <= E: B, tagged `Meta.Damage.Explosive.Radius.Inner`
   - E < d < R: `B x ((1 - F) + F x clamp((d - R)/(E - R), 0, 1))`, tagged `.Outer`
   - d >= R: 0
   - then floored at M (a missing M reads as 0). Status: NATIVE (`0x6F06540`, `0x6F06792` to `0x6F06831`), documented in [Damage Pipeline 1.1](../../pipelines/Wardogs_DamagePipeline_v2.md).
2. Vehicle factor `f`: the source tag, its context, `DamageType.Explosive` and the ring tag go through the same evaluator as an infantry hit. Every selected vehicle-row and generic-row entry applies in category order; a `Percentage_Ongoing` entry with amount `a` multiplies the running value by `1 + a/100`; `Add` adds a flat value; the result is clamped at 0 once (`0x6BB6FB0`). Status: NATIVE for the arithmetic, FOUND for the entries (`DT_GlobalDamage_VehicleData*`: 576 of 665 entries are `Percentage_Ongoing`, 5 are `Add`).
3. Damage to the section: `A x f`, routed through the section order of [Vehicle Damage Pipeline 4](../../pipelines/Wardogs_VehicleDamagePipeline_v1.md) (pre routing, own health, post routing, with each section's radial skip flags honoured).
4. Hits to destroy: the number of blasts until the main health is 0. For a main-body application with no routing this is `ceil(MainHealth / (A x f))`. Floats are single precision, as in the evaluator.

## Settled points

R52-2. **How Percentage_Ongoing applies.** It is relative: -20 means x0.8, -95 means x0.05, +200 means x3. The entries multiply, they do not add. The wiki (vehicle damage article, "A rule of -95% leaves 5%") and the pipeline docs treat it the same way. The infantry rules and the turret rules use the same evaluator, so no difference. Status: NATIVE.

R52-3. **Rockets use the same table as every other explosive, not a separate path.** The evaluator has no per-weapon branch. A rocket meets the generic rocket entries, the caliber entry (for example `Explosive.Rocket.84mm`) and the ring entry (`Explosive.Radius.Inner` or `.Outer`), plus any hit-location entry. No vehicle entry requires a weapon tag (the vehicle viewer notes the same). The tool skips entries that need instigator or target tags, as the viewer does. Status: FOUND.

R52-4. **A rocket is a radial hit only, not a direct hit plus a blast.** An exploding projectile skips the direct-damage block (`0x6B729A3`, `0x6B729AA`), so the vehicle takes the radial application with the Inner or Outer ring tag and does not also take a `DamageType.Projectile` hit. The blast origin is the impact point backed off along the flight path by half the projectile length, which is inside the inner radius for every launcher used here (back-off 127 cm for the 122 mm rocket against E 200 cm, 12.7 cm for the 84 mm against 400 cm, 36 cm for the 93 mm against 250 cm, 71 cm for the 72 mm against 200 cm, 4.9 cm for the 40 mm against 250 cm). So a rocket that hits the vehicle is an Inner-ring hit. Status: NATIVE for the skipped block; FOUND for the back-off values (`vehicle-hitboxes.json`, [rocket impact audit](round8-explosive-viewer-audit.md)). The impact point itself (what the rocket actually collides with) is not traced.

R52-5. **Radial falloff.** Full B up to E, then linear down to `B x (1 - F)` just inside R, 0 at R, floored at M. Status: NATIVE. Example: the MAAWS rocket (B 100, E 4 m, R 10 m, F 1.0, no minimum) does 100 up to 4 m and 50 at 7 m. A Humvee needs 2 MAAWS rockets inside 4 m and 8 at 7 m (the tool's `outer_mid` column), because the Outer ring also loses the large Inner bonus (Humvee MAAWS factor 3.9 Inner, 1.3 Outer).

R52-6. **Vehicle armor and location multipliers.** There is no armor angle, thickness, side or reactive armor in the damage data. The vehicle rows are keyed by damage type and, for a few entries, by hit location. Status: ABSENT for angle, thickness, side and ERA (the T-72B3 has no ERA data; see [Vehicle Damage Pipeline 3.1](../../pipelines/Wardogs_VehicleDamagePipeline_v1.md)). FOUND for the location entries that exist: 40 mm grenade on an engine (-95 % on the T-72B3) and rocket on the Little Bird tail (+200 %, per the vehicle articles). The tool reads each section's own hit tag, so every such entry is applied to the section it names. Locations matter only through which section the blast resolves to, which is taken from the vehicle's first component hit (Vehicle Damage Pipeline 4.1).

R52-7. **Which section the blast hits.** The tool reports the main-body count (rule factor of the main health section, as in the Explosives Reference) and the fewest blasts through any single section. They differ in one case: the B-13 rocket on the Little Bird family, 5 on the main body and 2 through the tail rotor. Status: derived; the real section depends on the first component hit and is not predictable without geometry (O-1 below).

R52-8. **Radial skip flags and routing.** Radial events skip the Pre, Post or Simultaneous routing on sections that set the skip flag (12 sections, the tracks). The tool honours them. Status: NATIVE for the flags, FOUND for which sections set them.

## Not settled

- O-1. **Distance in play.** The counts are for d <= E (Inner). A real blast's distance is measured to the accepted hit point, not the vehicle centre, and the chosen point (first unoccluded sample) is not predictable without geometry. Outer-ring counts for the midpoint between E and R are in the JSON as a guide only. Status: NATIVE rule, geometry not modelled.
- O-2. **Several components per blast.** The game keeps one hit per component and then drops repeated non-empty hit-location tags, so a blast near several parts applies fewer times than there are contacts, but possibly to more than one section. The tool counts one application. Real counts can be lower. Status: NATIVE, not modelled.
- O-3. **Hit-location entries for a blast.** The location tag of each contact selects its rule entries, but the section takes its health from the first hit. The tool uses the main health section's own tag for the main-body count. Status: NATIVE (Vehicle Damage Pipeline 4.1).
- O-4. **AT mine trigger and distance.** The mine detonates at its own position (ground), so the distance to the vehicle's hit points is not zero; the tool assumes Inner. E is 3.75 m. Friendly vehicles also trigger it ([AT Mine](../../_wiki/equipment/at-mine.md)). The mine's two `SimulateRadialDamage` sites were not told apart (R41-19). Status: FOUND, partial.
- O-5. **9K333 Verba guidance.** The data gives the rocket's damage, but not whether the weapon needs a lock or is guided. The counts treat it as a plain rocket. Status: ABSENT.
- O-6. **Server overrides.** Mode, difficulty or server rules could scale vehicle damage. None was found in the client data. Status: SERVER, not visible.
- O-7. **Repair and regeneration.** The tables ignore both. Status: not modelled.
