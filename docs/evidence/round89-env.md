# Round 89 env: handheld optics, FX field tables, Recon Tower piece names

Items: V4-21, V4-23, V4-24, and the Object Collision Viewer name polish.

## V4-21 handheld optics

`BH_PrototypeMaskedScopes_ExtensionData_C` sits on the item actor fragment of four items under `Plugins/GameFeatures/Items/{Binoculars,RangeFinder}/Content/Data`: `ID_Binoculars_Standard`, `ID_Monocular`, `ID_RangeFinder_Standard`, `ID_RangeFinder_Expensive`. Fields read: `DefaultAdsZoom` (4 on all), `AdsZoomMin` (Monocular 3, both range finders 2), `AdsZoomMax` (Binoculars 4, Monocular 5, Infrared Range Finder 8; the standard Range Finder has none), `MaskedScopeWidgetClass` (`W_HUD_MaskedScope_C` on all four), `MaskedScopeCount` (2 on Binoculars and Infrared Range Finder). The Infrared Range Finder also has a `PPi_IR` post-process blend and four ghillie gear pairs it ignores. Names and prices from `assets/data/loadout-builder.json`.

ADS FOV uses the sight rule from round 46 and 79 (base 72 when the test value, here max(default, max zoom), is 3.25 or more). All four test at 4 or more, so base 72. Generated by `_tools/sight_tables.py` (`handheld` block, `handheld` key in `sights.json`). Not measured on screen.

## V4-23 and V4-24 field tables

`_tools/fx_data_tables.py` writes `content/Wardogs_FX_Field_Tables_v1.md`: 35 `PDA_Explosion_C`, 9 `PDA_PhysicalMaterialResponse_C`, 34 `PDA_VehicleProp_C` (the 35th file in that folder is the `DT_VehiclePropList` table, covered on the combat data tables page), 48 `PDA_MuzzleFlash_C` and 47 `PDA_MuzzleFlashAttachement_C`. Every property the assets store is a column. The existing VFX and Muzzle Flashes pages already carried the short tables; the new page adds the missing fields (small core and streak values, debris scale, fireball distances, camera shake class, remains, per-size explosion effect lists, vehicle prop meshes/scales/colours, flash colours, gas and spark and light values, pattern values).

Findings: the two AK74-M assets (`DA_MuzzleFlash_AK74-M`, `DA_MF_AK74-M_Default`) are an ordinary recipe/device pair (recipe names its device in `DefaultMuzzle`); nothing else in the exports references them, and no weapon or attachment item names a flash asset, so the weapon-to-flash link is by asset name only. `Hex` values stored next to HDR flash colours do not match the RGB values and are left out. Units and class defaults are not in the export.
