# Wardogs: Inventory Ammo Packing (curves, asset and magazine multipliers)

*Source: every `CurveFloat` under [`Content/GameMechanics/Inventory/InventoryMagPacking`](https://github.com/Kiyogitpy/wardogs-data-docs/tree/main/data/Wardogs/Content/GameMechanics/Inventory/InventoryMagPacking), the shared [`CR_CombineAmmoCurve`](https://github.com/Kiyogitpy/wardogs-data-docs/blob/main/data/Wardogs/Content/GameMechanics/Inventory/CR_CombineAmmoCurve.json) one folder up, the [`DA_InventoryMagPackingData`](https://github.com/Kiyogitpy/wardogs-data-docs/blob/main/data/Wardogs/Content/GameMechanics/Inventory/InventoryMagPacking/DA_InventoryMagPackingData.json) asset, and the magazine items that carry the two multiplier fields. Every table below is generated by [`_tools/ammo_packing_tables.py`](https://github.com/Kiyogitpy/wardogs-data-docs/blob/main/_tools/ammo_packing_tables.py); do not edit it by hand.*

This is the data behind the inventory operations that move loose rounds into a magazine, out of one, or between two magazines. It is not the combat reload. The magazine multiplier fields and the native consumers (function RVAs, call sites) are recorded in the "Obfuscated magazine fields" note of [Attachments and Platforms](Wardogs_AttachmentsPlatforms_v1.md) (limitations section); this page adds the curve data. Related: [Weapons](Wardogs_GameFeatures_Weapons_v2.md) and [Ammo](Wardogs_GameFeatures_Ammo_v2.md).

**What is data and what is inferred.** Keys, curve references, tag entries and magazine values are read from the exports. The export stores no axis labels. Reading the input as the **round count** and the output as a **time** (probably seconds) is inference from the native code (the curves are evaluated at a round count and the result is multiplied by the magazine field) and from the key ranges; no unit is recovered. Every example below is **derived**, not observed in game.

How the six slots are used, in the order the native code reads them (native notes from round 27; see the attachments page):

- **Combine ammo** (`UWDPlayerInventoryComponent::CombineAmmo`): `curveA(rounds) x field(+0x6C)` of the **source** magazine plus `curveB(rounds) x field(+0x68)` of the **target** magazine (order read in round 91, see below). Each curve is taken from a per-caliber map (`+0x1C8` for A, `+0x218` for B) searched up the gameplay-tag parents, or from the default curve (`+0x30` for A, `+0xB8` for B, both [`CR_CombineAmmoCurve`](https://github.com/Kiyogitpy/wardogs-data-docs/blob/main/data/Wardogs/Content/GameMechanics/Inventory/CR_CombineAmmoCurve.json)) when no tag matches.
- **Load ammo** rule (`UWDCustomInventoryOperationRule_LoadAmmo`, vtable slot 86): second-curve value (`+0x218` map, else `+0xB8`) times `+0x68` of the magazine.
- **Per-round interval** (caller `0x754B640`): first-curve value times `+0x6C`, divided by the round count.
- **Combine loose ammo** (`+0x140` default [`CR_CombineLooseAmmoCurve_Default`](https://github.com/Kiyogitpy/wardogs-data-docs/blob/main/data/Wardogs/Content/GameMechanics/Inventory/InventoryMagPacking/CR_CombineLooseAmmoCurve_Default.json), `+0x268` per-caliber map): the slots are in the asset, but **no native consumer was traced** for them in the earlier rounds; their use for combining loose rounds is inference from the names.

**Source and target order (static reading, round 91).** `CombineAmmo` (`0x6B554B0`) walks the magazine entries of an operation with two indices, a low one and a high one. The low entry is the **target**: its capacity is the magazine item's cap (`+136` of the item data), its round count (`+24`) is raised. The high entry is the **source**: its count is lowered. The number moved each step is `min(source rounds, capacity - target rounds)`. When the target is full the low index advances; when the source is empty the high index retreats; the loop ends when they meet. For each step the time helper `0x6B5E500` is called with the number moved, the source magazine's data as the extract argument and the target's as the load argument: extract term = curve from the `+0x1C8` map (default `+0x30`) at the number moved x the **source** magazine's `+0x6C` factor; load term = curve from the `+0x218` map (default `+0xB8`) x the **target** magazine's `+0x68` factor; the two are added. A separate first call site passes only the load term (extract flag 0; which operation it serves was not read). Still a reading of unreviewed decompiler output; the sum being seconds stays inferred.

Each map entry is a runtime float curve with an inline curve (`EditorCurveData`) and an external curve. Only the 5.45 mm entries have inline keys (0 -> 3, 100 -> 6, identical in all three maps) and every other inline curve is empty. It matters here that every entry also has an `ExternalCurve`: the engine's runtime-curve type reads the external asset when one is set, so the per-caliber curves in section 3 are the effective ones and the 5.45 mm inline keys are inert (inference from standard engine behavior; the native evaluator `0x6C2F100` and its curve read were not re-traced this round). This corrects the earlier note, which treated the 11 empty entries as "no override": all 12 calibers override the default curve through their external assets.

## 3. The curves

Keys are `rounds -> time`, all linear (`Linear` in the Interp column), which this page evaluates with constant extension past the last key (the assets list `RCCE_Constant` for the map curves; for the standalone curve assets the extrapolation mode is not stored in the export). The default-value column is the curve's fallback value as stored; the 45 ACP extract and load curves store 0.3 and 0.4 where every other curve stores 1.0 (no consumer of the default value found).

## 6. Native consumers (round 41, static disassembly, decompiler output unreviewed)

- **Curve choice by caliber tag, with a parent search.** `0x6C2F100` looks the item's caliber tag up in the map; when the tag is absent it asks for the tag's **direct parent** and tries again, until a hit or no parent is left. So `Id.Item.556mm.Tracer` resolves to the `Id.Item.556mm` entry. Only if the whole chain misses does the caller use the default curve.
- **Which map does what.** `+0x1C8` is the **extract** map (default `+0x30`), `+0x218` the **load** map (default `+0xB8`), `+0x268` the **combine-loose** map (default `+0x140`). `0x6B5E500` reads `+0x1C8` / `+0x30` and `+0x218` / `+0xB8`; the load rule (`UWDCustomInventoryOperationRule_LoadAmmo` slot 86, `0x6C47420`) reads `+0x218` / `+0xB8` for a load into a magazine and `+0x268` / `+0x140` for combining loose rounds of one caliber.
- **Input and output.** The curve is evaluated at the **round count** (`0x6B5E566`: the integer argument converted to float, then `0x6C26830`, the rich-curve read of the external curve). The result is multiplied by the magazine's `+0x6C` field (extract term) or `+0x68` field (load term) and the two are added (`0x6B5E500`, called twice by `CombineAmmo` `0x6B554B0`). Whether the sum is seconds is still inferred from its use as an operation duration.
- **Defaults and the int `48`.** The scalars at `+0x2B8`, `+0x2BC`, `+0x2C0` are unset in the asset; `+0x2C4` is 48 (the asset's own value). Their consumers were not found (the load rule does not read them).

## Still Not Pulled / Limitations

- The unit of the output (seconds assumed) and the input (round count) are inferred, not recovered; no UI or timer consumer was read this round.
- Native consumer for the combine-loose map and default: found in round 41 (section 6). The stored int `48` at `+0x2C4` and the three default-valued scalars are still unexplained.
- The parent-tag search is found (section 6); which tags the shipped magazines carry beyond the 12 keys is not listed here.
- Standalone curve assets do not store an extrapolation mode in the export; clamping past the last key is assumed.
- No in-game timing was measured, so none of the example values are verified against play.
