# Wardogs: Progression Tables (skills, live curves, currencies, cosmetics)

*Source: the data tables whose row type is `WDMetaSkillEffectsTaggedTableRow`, `WDLiveCurveTableRow`, `WDCurrencyDefinition` or `WDCosmeticData`, plus the curve tables and assets they point at, all under [`data/Wardogs`](https://github.com/Kiyogitpy/wardogs-data-docs/tree/main/data/Wardogs). GameplayEffect numbers come from [`assets/data/ge-values.json`](https://github.com/Kiyogitpy/wardogs-data-docs/blob/main/assets/data/ge-values.json). Every table below is generated by [`_tools/meta_tables.py`](https://github.com/Kiyogitpy/wardogs-data-docs/blob/main/_tools/meta_tables.py); do not edit it by hand.*

This page lists the small progression tables that no other page covered row by row: what each role skill does in numbers, the live curves that scale challenge rewards, the two currencies, and every cosmetic row. Context lives on other pages: the role unlock trees, XP and the gold market are on [Meta](../content/Wardogs_Meta_v2.md), the reward formulas on [Session-Event Reward Lookups](../content/Wardogs_RewardLookup_SessionEvents_v1.md), and the challenge trees on [Challenges and Session Events](Wardogs_Challenges_v1.md). What the Medic skills change in item and revive numbers, and the Medic nodes that have no data row, are on [Medical and Healing](Wardogs_Medical_v1.md).

Labels: **Data** is read straight from the export. **Native** is read from the game code (nothing on this page needed it). **Derived** is worked out from Data values. "Not traced" means nobody has followed it yet.

The skill tables hold the 6 role tables and 4 plugin tables (C4, PrototypeMaskedScopes, Spotting, Lockpicking). The live curve tables are the 8 `DT_Challenges_Curves_*` tables, one in the BuildableRewards plugin, and `DT_Meta_RewardScalingCurves`.

## 2. Role skills

- **Data.** A skill row is keyed by a `Meta.Role.<Role>.<Skill>` tag. It holds a list of effect groups. Each group has a slot tag (the "Applies via" column: `Meta.Skill.Item`, `Meta.Skill.Vehicle`, `Meta.Skill.Character`, `Meta.Skill.Character.HeldItemUpdated`, `Meta.Skill.SupplyCrate`, `Meta.Skill.Revive.Target`) and, inside it, one GameplayEffect class, its custom magnitudes and extra data.
- **Data.** A magnitude is an attribute tag with a base value (there are 62 magnitudes in 59 rows, three rows have two; 61 have base 1.0 and a curve; `Meta.Role.Recon.ColdBlooded` has a literal 2.0 for `Attribute.Gameplay.CustomDepthStencilValue` and no curve table) and a curve row in a `CT_*Skills` table. The "Applies to" column is the extra data: an item filter (`RequireTags`/`IgnoreTags`), a vehicle filter (a tag query), or default attribute values.
- **Data.** The effect classes are resolved through `ge-values.json`. Most effects have one modifier whose value is `SetByCaller`, which means the number is supplied when the effect is applied. The skill's curve value is the number supplied, so "Multiply `Attribute.X` by the skill value" reads as: the attribute is multiplied by the curve value for the player's skill rank. Three skills grant a `Skill.*` tag and have no modifiers or curve.
- **Derived.** The curve keys (time 0, 1, 2 ...) look like skill ranks and the value is what rank gives. For example the Driver ADS skill runs 1.0, 0.8, 0.7, 0.6 at ranks 0, 2, 3, 4: a lower `AimTime` multiplier means a faster ADS. The export does not say that the key time is the rank, and the sign convention per attribute is not confirmed in game code. Not traced.
- **Open.** The 62 skill tags are in the UI node table [`DT_CharacterSkillNodes_Data`](https://github.com/Kiyogitpy/wardogs-data-docs/blob/main/data/Wardogs/Content/UI/Data/DT_CharacterSkillNodes_Data.json) (name and description, 131 rows in all) and in the tree layout asset [`DA_UI_RoleSkillTree_NodePresetData`](https://github.com/Kiyogitpy/wardogs-data-docs/blob/main/data/Wardogs/Content/UI/Features/Frontend/Mastery/Roles/Data/DA_UI_RoleSkillTree_NodePresetData.json). None of the 62 appears in the unlock tree `DT_MetaTree_Roles`, which holds only items and vehicles (264 nodes, all costed in cash). Round 36 result: the layout lists 130 nodes, of which only these 62 have an effect row; the other 68 (for example `Meta.Role.Infantry.StrongArm`, `Meta.Role.Support.ReloadSpeed.LMG`) have a name and a grid position but no effect, no level and no cost anywhere in the client. Skill points exist only as six `Attribute.Meta.Currency.SkillPoint.Role.*` modifiers (SetByCaller) in `GE_Meta_ResourceChange`; they are not in `DT_CurrenciesDefinitions` (Cash and Gold Bars only), and no table, reward row or mission grants them. The node upgrade request (`Pragma_PlayerData_UpgradeNodeRequestProto`: NodeId, TreeId and the MetaTrees, Currency and PlayerMastery content versions) goes to the backend, which checks the exported tree. See [round 36 economy](https://github.com/Kiyogitpy/wardogs-data-docs/blob/main/docs/evidence/round36-econ.md#4-skill-unlocks-and-skill-points).

## 4. Live curves

- **Data.** A `WDLiveCurveTableRow` is a gameplay tag plus a pointer to a `CurveFloat` asset (`CRV_*`). The table below decodes each asset: the keys are input then output, and the interpolation is the key mode (`Constant` holds the value until the next key, `Linear` blends, `Cubic` is a smooth curve).
- **Data.** A reward formula variable of type `ScalingValue` names a curve tag in `ScalingValueCurveTag`. The "Reward formula rows" column lists the formula rows (in any `DT_ChallengeRewards_*` table) whose variable names that tag exactly.
- **Derived.** The last column lists the state trees that name one of those reward tags in a calculate or grant step. The tag join is by name; whether the game does the same join is not traced.
- **Data.** Two keys can share an input (for example `-50` twice in `FactionScoreDifference` and `10` twice in `PlayerCountCashScalar`). That is a step in the curve as exported.
- **Data.** The three rows of `DT_Meta_RewardScalingCurves` (`PlayerCountCashScalar`, `PlayerCountXPScalar`, `MatchScoreScalar`) are not named by any reward formula in the export, and `PlayerCountXPScalar` points at the same asset as `PlayerCountCashScalar`. Where the game reads them is not traced.
- **Data.** The two `EndOfMatch` curves are named by rows of `DT_ChallengeRewards_EndOfMatch`, which is not one of the five session-event formula tables, so the Challenges page does not list them.

## 6. Cosmetics

- **Data.** A `WDCosmeticData` row has an entity id (the item or vehicle it skins), a category tag (the set), an archetype, UI texture references, a skin definition asset and an optional name override. Icon names only are listed here, no images.
- **Data.** "Gold market" is a join on the cosmetic tag to [`DT_GoldMarket`](https://github.com/Kiyogitpy/wardogs-data-docs/blob/main/data/Wardogs/Content/Meta/Collection/DT_GoldMarket.json) (cost in Gold Bars). Rows with `-` have no market row; their source is not stated in the data.
- **Data.** "Slot / vehicle filter" comes from the sibling `WDVehicleSlotPartRow` table (the bobblehead `*_SlotParts` tables): the vehicle slot the part fits and the vehicles it is limited to (none means no filter).
- **Data.** `DT_Cosmetics_Debug` has no rows. `DT_Bobblehead_HeavyHelmet_Cosmetics` names the localization key `Cosmetic.Bobblehead.Grenade.DisplayName`, which is the Grenade key, and the Faction row's key is spelled `Cosmetic.Bobblhead.Faction.DisplayName`. Both are as exported.
