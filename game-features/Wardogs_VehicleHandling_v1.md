# Wardogs — Vehicle Parts and Handling

*Extracted from cooked game data as JSON. Source: [`Wardogs/Plugins/GameFeatures/Vehicles`](https://github.com/Kiyogitpy/wardogs-data-docs/tree/main/data/Wardogs/Plugins/GameFeatures/Vehicles). Every table below is generated by [`_tools/vehicle_part_tables.py`](https://github.com/Kiyogitpy/wardogs-data-docs/blob/main/_tools/vehicle_part_tables.py) (`--write` refreshes them in place). Values are shown as stored.*

> **Scope:** this page lists the 93 `ModularVehiclePart` (`VP_*`) assets and the handling numbers of the 26 drivable variants (wheeled, tracked, rotary). The vehicle plugin overview is [Vehicles (feature)](Wardogs_GameFeatures_Vehicles_v2.md). Damage, health sections and hit routing are in [Vehicle damage pipeline](../pipelines/Wardogs_VehicleDamagePipeline_v1.md); the slot and part assembly rules are in its [section 5.4](../pipelines/Wardogs_VehicleDamagePipeline_v1.md#54-hits-to-destroy) ("Data, assembly") and are not repeated here.
>
> **Labels:** **Data** is read from the export files. **Derived** is computed from Data by the generator. "Not traced" means no native code was followed. No engine code was read for this page.
>
> **Units:** the export does not label most fields. Treat speed, fuel, mass, torque and brake numbers as relative values. Only suffixed fields (`_mps`, `_deg`) carry a unit. Curve peaks use the curve's own value and its time axis (RPM for engine curves).

## 1. How a variant reaches its handling numbers

**Data.** A variant (`VV_*`) names a platform; the platform and the parts placed in its slots each hold fragments. The `MVF_VehicleConfig` fragment points at a config asset, and the config points at the handling assets. A part can carry its own config (for example `VP_WHL_02_Pickup_Config`), and the generator takes the config of the last module that has one (**Derived**; the native replacement rule is not traced).

| Family | Config type | Handling assets it names |
|---|---|---|
| Wheeled | `MWheeledVehicleConfigDataAsset` | `…Characteristics` (mass, brakes, assists), `…EngineTransmission` (torque curve, gears), two or three `…Axles` (steer, torque share, differential) each naming a `…Wheel` asset (tyre radius, springs, dampers, brake torque) and a tyre model, plus arcade and input assets |
| Tracked | `MTrackedVehicleConfigDataAsset` | `…EngineData` (torque curve, gears, differential), `…DynamicsData` (second engine curve, steer curve, gears), `…SuspensionData`, `…WheelData`, track bones |
| Rotary | `BHRotaryVehicleConfigDataAsset` | `…Body` (mass override), `…Engine` (rotor RPM), `…Drag`, `…FlightCharacteristics` (hundreds of assist conditions) |

All three families also name a prediction-settings asset, a sensors asset, camera assets, input controls and the `DA_GameplaySystems_*` asset (its damage tag is covered in the damage pipeline). Stationary weapons (`STN_*`) and `FWG_01` have a base config only and no handling numbers, so they are left out of the handling tables.

## 2. Common sheet: seats, speed, fuel, mass

**Data.** `Stats` is the vendor spec sheet (`WDVehicleStatsDataAsset`: MaxSpeed, MaxFuel, FuelEconomy, MaxSeats; see [Vehicles (feature)](Wardogs_GameFeatures_Vehicles_v2.md) for the full stats table). `Seat setups` counts the entries of the assembled seat assets; a variant with a mounted gun adds the gun's own seat asset to the platform's. Body mass is the physics mass: `Characteristics.Mass` for wheeled and the `Body` mass override for rotary. Tracked configs set no total mass: only track and sprocket mass appear in their engine data (§4). The collision-fragment mass is `VehicleMass` of the destruction fragment (`WD_MVF_DestructionInvokerFragment`) and is a different quantity from the physics mass.

Where the seat setups and `MaxSeats` differ (`WHL_05_Humvee_RingMinigun` 5 and 4, `WHL_07_ArmouredBattle` 5 and 3) the seat asset lists more setups than the stats sheet counts; the reason is not traced.

### Seat names (`WDVehicleSeatNameOverrideRow`)

**Data.** Each vehicle plugin's `GameFeatureAction_DataRegistrySource` adds a `DT_VehicleSeatOverrides_*` table to the `VehicleSeatNameOverrides` registry. A row is keyed by a variant tag and holds one entry per seat index (text shown when a player enters the seat and, optionally, when leaving). Only the rotary and stationary families have such tables: all 9 tables are below (12 rows). Wheeled and tracked variants have none. The seat-map field name is obfuscated in the export; the text keys (`...Enter.<Name>.OutcomeText`) show it is the enter text. Where the exit text is empty the table shows `-`. How the UI picks a row for a seat is **not traced**. Stationary weapon build data is on the [Buildables](Wardogs_Buildables_v1.md) page.

## 3. Wheeled vehicles

**Data.** The torque curve is a `CurveFloat` (`CRV_Torque` in each vehicle's `Data/Curves`; WHL_02, WHL_05 and WHL_06 share the 475 @ 5,500 shape and differ in `TorqueScale`). `—` means the asset does not set the field, so the native default applies (traced in round 45, see [Native defaults](#10-native-defaults-for--fields)). The gear list has six entries; the sixth is the largest ratio and is probably reverse (not traced). Torque share and steer angle are per axle, front first. Wheel assets store three values per field (intact, damaged, destroyed, shown by the tyre radius falling 0.45, 0.345, 0.26 on the dune buggy); the tables show the intact value. Brake torque, damper and spring units are not labelled.

## 4. Tracked vehicles

**Data.** A tracked config names two engine-side assets that both hold a torque curve and gear list: `EngineData` (external `CRV_TrackedVehicle_TorqueCurve_*` curve, differential ratio, extra power ratio) and `DynamicsData` (inline `EngineTorqueCurve`, `MaxRPM`, `Gears`, steer curve). Which one the game uses for drive force, or whether it blends them, is not traced; both are shown. TNK_01 Artillery, TNK_01 Heavy and TNK_04 share the same torque curve, suspension and wheel data and differ in config (the T-72 differs from TNK_01 in its damage rows, see the [T-72 armor note](../pipelines/Wardogs_VehicleDamagePipeline_v1.md#t-72-armor-tnk_04)). `—` means the field is not set in that asset. The `SPW_01`, `SPW_02` and `SPW_03` variants share one config.

## 7. Other handling-named assets that are not handling

- **`DA_Vehicle_BrakingSurface_*` (6) and `DA_Vehicle_Skidding_{Slow,Medium,Fast}_*` (16)** are `WDAudioData`: surface-tag to sound-wave maps (dirt, gravel, water, asphalt). They hold no braking or skid physics. Braking force lives in the wheel assets (wheeled `BrakeTorque`, tracked `BrakeForce` and `SpeedToBrakeForce`).
- **`CC_HDR_ATT_DuneBuggy_Engine`** (and its `CC_HDR_ATT_*` siblings under `Content/Audio/Attenuations/HDR`) is an audio attenuation curve, not an engine torque curve.
- **`DA_VehicleSensor(s)_*`** hold only a water-logging sensor position and grace period (all 9 `MVehicleSensorsDataAsset` assets; the grace period is set in 7 of them), and for rotary vehicles landing-strut sensor shapes, an altitude sensor length and the on-ground collision channel. The effect of the water-logging sensor is not traced.
- **`DA_SeatSettings_*` / `…_SeatSettings`** are animation, camera and access-point data per seat (`BHSeatSettingsDataAsset`); only the seat counts are used above.

## 9. Open items

- Which of `EngineData` and `DynamicsData` drives a tracked vehicle, and the unit of the torque and brake numbers, are not traced.
- Gear order (whether the last wheeled ratio is reverse) is inferred, not traced; the native default list is two entries (3.0, 5.0) with automatic reverse on, which fits "last = reverse" ([round 45](../docs/evidence/round45-b.md), item 5).
- `FlightCharacteristics` and `DA_ArcadeControls_*` are not decoded.
- Whether the boost switch (`bEnableBoost`, false in every wheeled asset) gates the stored boost scale is not traced.

## 10. Native defaults for `—` fields

**Data.** A cooked asset stores only the properties that differ from the class default, so every `—` above (and every missing `Values[n]` key of a wheel asset) takes the value the native constructor writes. The constructors were read statically in [round 45](../docs/evidence/round45-b.md) (items 1, 4 and 7); the filled-in values for every asset are in [`vehicle-native-defaults.json`](../assets/data/vehicle-native-defaults.json), rebuilt by [`_tools/r45_vehicle_defaults.py`](../_tools/r45_vehicle_defaults.py). A missing key is the default, not zero.

| Engine and transmission (`0x530F660`) | torque scale 1.0, friction torque 50, **idle RPM 1,000**, limit RPM 6,500, limiter time 100, inertia 0.25, boost switch off, boost scale 1.0; auto change, auto reverse, auto clutch and rev matching on; change time 100, gear up / down ratio 90 / 80, crawling gear 1, **gear ratios 3.0 and 5.0**, final ratio 3.0 |
